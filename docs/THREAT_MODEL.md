# Veylora --- Threat Model

## 1. Scope

This is an initial threat model for the local Veylora development
prototype.

It identifies important assets, trust boundaries, threats, current
mitigations, and remaining verification work. It is not a formal
security assessment, penetration test, or guarantee of security.

The current application is intended for local, single-user research and
demonstration.

## 2. Assets

-   Original BPI Challenge 2017 event log and derived case-level files.
-   Research code, analytical scripts, and model outputs.
-   Experiment configuration and synthetic simulation assumptions.
-   Git repository history and published portfolio artifacts.
-   Integrity of metrics, recommendations, and evidence provenance.
-   Downloadable optimization audit reports.
-   Local environment configuration and dependency packages.

## 3. Trust Boundaries

1.  Files imported from outside the application.
2.  CSV artifacts loaded from the configured local processed-data
    directory.
3.  User-controlled filters and scenario parameters.
4.  Registered analytical tools invoked by the optimization agent.
5.  Synthetic data generated by the process simulator.
6.  Files exported by the dashboard, including JSON audit reports.
7.  Local Python environment and third-party dependencies.

## 5. Agent-Specific Security Boundary

The Autonomous Optimization workflow uses a registry of analytical
tools.

The current tool set exposes defined process-analysis, opportunity
retrieval, causal assessment, and synthetic experiment functions.

The current workflow: - Does not provide arbitrary shell execution
through its registered tools. - Does not provide arbitrary Python code
execution through its registered tools. - Records tool execution results
and audit information. - Produces recommendations for human review. -
Does not execute operational business changes.

These controls reduce the scope of the current prototype's tool
interface but do not constitute a formal security audit.

Any future addition of language-model planning, file-writing tools,
external connectors, or operational actions must receive a separate
permission and threat review.

## 6. Assumptions and Exclusions

The initial release runs locally for one user and does not provide an
authentication boundary.

This is an explicit deployment limitation, not a security guarantee.

The current prototype does not provide a complete: - Enterprise
access-control system. - Centralised audit service. - Security
monitoring and alerting system. - Incident response process. - Backup
and disaster recovery service. - Multi-user session isolation design.

A hosted or multi-user deployment requires separate access-control,
session, network, logging, backup, privacy, and incident-response
design.

## 7. Verification Backlog

-   [ ] Add input file size and row-count limits.
-   [ ] Add comprehensive schema and timestamp validation.
-   [ ] Test NaN, infinity, malformed timestamps, and invalid numeric
    parameters across metric inputs.
-   [ ] Add dependency vulnerability scanning.
-   [ ] Define explicit export column allow-lists.
-   [ ] Review Streamlit network settings for the intended deployment.
-   [ ] Inspect repository history for accidentally committed raw or
    derived data.
-   [ ] Add tests for tool permission boundaries and unexpected tool
    failures.
-   [ ] Define audit report integrity and provenance requirements.
-   [ ] Review local file permissions and report storage.
-   [ ] Define backup, recovery, and incident-handling procedures before
    any shared deployment.

## 8. Security Review Gate

Do not describe Veylora as secure for enterprise or production use based
solely on this initial threat model.

Before deployment beyond the local prototype, perform a
deployment-specific review covering:

-   Data rights and privacy.
-   Authentication and authorisation.
-   Network exposure.
-   Input validation and resource limits.
-   Dependency security.
-   Agent tool permissions.
-   Export and audit integrity.
-   Logging and sensitive-data handling.
-   Backup, recovery, and incident response.
